# Блок управления приводом turtle-bot

Прошивка для Arduino Nano: два мотора с квадратурными энкодерами, драйвер
L298N и Bluetooth-модуль HC-06. Бот принимает команды по Bluetooth,
стабилизирует скорость колёс ПИД-регулятором и отдаёт телеметрию.

## Состав

- Arduino Nano ATmega328P (новый загрузчик, 115200);
- драйвер L298N;
- два мотора с энкодерами;
- Bluetooth-модуль HC-06 (SPP).

## Распиновка

| Узел | Сигнал | Пин Nano |
|---|---|---|
| Правый мотор | IN1 / IN2 / ENA | D2 / D3 / D5 |
| Левый мотор | IN3 / IN4 / ENB | D4 / D7 / D6 |
| Правый энкодер | A / B | A0 / A1 |
| Левый энкодер | A / B | A2 / A3 |
| HC-06 | TX → D0, RX ← D1 | D0 / D1 |
| Индикация | LED | D13 |

Ограничения по подключению:

- HC-06 RX не 5V-tolerant — подключать только через делитель 5V → 3.3V.
- При прошивке по USB HC-06 отключить: загрузчик использует D0/D1.
- SoftwareSerial не используется: его PCINT-алиасы конфликтуют с ISR
  энкодеров на ATmega328P.

## Что нужно установить

- [VS Code](https://code.visualstudio.com/).
- Расширение **PlatformIO IDE**: в VS Code открыть Extensions, найти
  `PlatformIO IDE` и установить.
- PlatformIO Core устанавливается вместе с расширением. Для работы из
  терминала нужен путь к `pio` (см. вариант A ниже).

## Сборка и прошивка

### Вариант A: CLI

В этом окружении PlatformIO установлен в `~/.platformio/penv`, но не добавлен
в `PATH`, поэтому используется полный путь:

```bash
~/.platformio/penv/bin/pio run                 # сборка
~/.platformio/penv/bin/pio run -t upload       # прошивка
~/.platformio/penv/bin/pio device monitor      # монитор
```

Если `pio` доступен в `PATH`, команды можно писать короче:

```bash
pio run
pio run -t upload
pio device monitor
```

Монитор открывается на 115200 — скорость задана в `platformio.ini`
(`monitor_speed = 115200`).

### Вариант B: VS Code + PlatformIO IDE

1. Открыть папку проекта в VS Code.
2. Дождаться, пока PlatformIO установит платформу `atmelavr` и зависимости.
3. Использовать кнопки PlatformIO в статус-баре VS Code:
   - **Build** — сборка;
   - **Upload** — прошивка;
   - **Monitor** — последовательный монитор.

Скорость монитора берётся из `platformio.ini`, отдельно указывать 115200 не
нужно.

После старта в мониторе сразу идут кадры телеметрии:

```text
ack 0 0.0 0.00 mL=0.0 mR=0.0 oL=0 oR=0 iL=0.0 iR=0.0
```

Если плата со старым загрузчиком и прошивка не заливается, добавьте в
`platformio.ini`:

```ini
upload_speed = 57600
```

Для платы `nanoatmega328new` это не требуется: 115200 уже задано в
манифесте платы.

## Первый запуск HC-06

Модуль хранит скорость UART между включениями. Автоконфигурация при старте
управляется флагом `kEnableBtAutoConfig` в `src/app_config.h`:

- `false` (по умолчанию) — AT-последовательность не выполняется; модуль
  должен быть уже настроен на `kSerialBaud` вручную.
- `true` — прошивка при старте переводит модуль на `kSerialBaud`: сначала
  `AT+BAUD8`, при отказе — `AT+UART=115200,0,0`.

При `true` AT-команды принимаются только пока к модулю не подключён ПК.
Поэтому первый старт после прошивки должен пройти до подключения по
Bluetooth. Результат автоконфигурации показывается серией вспышек D13.

## Пульт с ПК

Подключение RFCOMM-канала:

```bash
sudo rfcomm bind rfcomm0 00:21:13:00:0C:E3 1
```

Запуск пульта:

```bash
python3 py_scripts/pc_control/controller.py /dev/rfcomm0
```

Клавиши:

| Клавиша | Действие |
|---|---|
| ↑ / ↓ | линейная скорость ±10% |
| ← / → | угловая скорость ±10% |
| Space | пауза / продолжить |
| q | выход |

Пульт повторяет текущую команду каждые 200 мс — это питает watchdog
прошивки. Используется только стандартная библиотека Python.

## Протокол

Команды (текст, `\n` — конец команды):

```text
set_speed <linear_mm_s> <angular_rad_s>
stop
power_stop
```

- `set_speed` — задать скорость: `linear_mm_s` — линейная скорость середины
  оси колёс, мм/с; `angular_rad_s` — угловая скорость, рад/с, плюс — против
  часовой;
- `set_speed 0 0` — обычная нулевая уставка: привод остаётся в замкнутом
  контуре и удерживает колёса на нуле; при переходе из ненулевой уставки в
  ноль PID-интегратор сбрасывается один раз;
- `stop` — свободный выбег: драйвер отключается, PID сбрасывается;
- `power_stop` — активное торможение L298N на 300 мс, затем выбег; повторные
  команды продлевают торможение;
- watchdog: если команда не получена более 1000 мс, выполняется `stop()`.

Телеметрия приходит раз в 200 мс:

```text
ack <n> <v> <w> mL=<ml> mR=<mr> oL=<ol> oR=<or> iL=<il> iR=<ir>
```

`n` — счётчик всех валидных команд (`set_speed`, `stop`, `power_stop`),
`v`/`w` — последняя уставка `set_speed` (после `stop`/`power_stop` — `0`),
`mL`/`mR` — измеренная скорость, `oL`/`oR` — ШИМ ±255,
`iL`/`iR` — интеграл ПИД.

## Структура проекта

```text
src/
  main.cpp                  точка входа Arduino
  app_config.h              общие настройки (скорость UART)
  motor_controller.*        композиция модулей
  bluetooth/                автоконфигурация HC-06
  chassis/                  моторы, энкодеры, ПИД, привод
  protocol/                 приём и разбор команд
  telemetry/                кадр телеметрии
py_scripts/pc_control/      консольный пульт
openspec/                   спецификации и backlog
```
